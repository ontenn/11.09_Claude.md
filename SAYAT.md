# Планёрка 15 — рабочий стол распределения задач

Корпоративный одностраничный рабочий стол. Цель — за 15 минут определить объём работ на день
со структурой сложности и зафиксировать план, доступный и с компьютера, и с телефона.

Сайт существует в двух версиях:

| Версия | Адрес | Что умеет |
|---|---|---|
| **Рабочая** (на claude.ai) | https://claude.ai/code/artifact/6a0d1430-29e3-4896-9d13-07c31aeae2ec | Всё: общий план на всех устройствах, загрузка документов, ИИ-проверка |
| **Публичная** (GitHub Pages) | https://ontenn.github.io/SAYAT.md/ | Планирование целиком; данные — в браузере устройства, без загрузки документов и ИИ |

- **Репозиторий:** https://github.com/ontenn/SAYAT.md
- **Исходник:** `index.html` (один файл, без сборки); версия для claude.ai — `planerka15.html`
- **Дата создания:** 11 сентября 2026

## 1. Механика 15 минут

В шапке три инструмента, которые вместе задают регламент планёрки:

| Элемент | Назначение |
|---|---|
| Таймер планёрки | Обратный отсчёт 15:00, старт/пауза/сброс; после нуля уходит в минус красным |
| Шкала объёма работ | Сумма часов плана против нормы дня (норма редактируется прямо в шапке, по умолчанию 8 ч) |
| Лента готовности | 5 шагов: собрать задачи → оценить сложность → расставить приоритеты → уложиться в норму → зафиксировать контроль |

План считается закрытым, когда все пять шагов зелёные, а шкала не в перегрузе.

## 2. Структура сложности

Три уровня с весами — они дают и часы, и сопоставимую «тяжесть» дня в баллах:

| Уровень | Код | Ориентир | Вес |
|---|---|---|---|
| Лёгкая | Л | до 1 часа | 1 |
| Средняя | С | 1–3 часа | 2 |
| Высокая | В | свыше 3 часов | 3 |

Приоритеты: **Критично** (срыв сроков или обязательств), **Высокий** (важно на этой неделе),
**Обычный** (плановое). Критичные и высокие задачи помечены цветной полосой слева.

План дня сгруппирован по уровням сложности, внутри группы — сортировка по приоритету.
В заголовке блока — число задач и суммарный вес в баллах; у каждой группы — количество и часы.
При вводе часов уровень сложности подставляется автоматически.

## 3. Блоки рабочего стола

1. **Календарь нагрузки** — месяц; в каждом дне полоса заполнения относительно нормы,
   точка при перегрузе; клик по дню переключает весь стол на этот день.
2. **План дня** — задачи по структуре сложности, фильтры «Все / Критичные / Лёгкие / Средние / Высокие».
3. **Предстоящие цели** — срок, прогресс по связанным задачам, остаток часов; просроченные и
   ближайшие сроки подсвечиваются.
4. **Завершённые** — за выбранный день и за 7 дней: количество, фактические часы, баллы сложности;
   выполненные пункты контроля. Отметку можно снять обратно.
5. **Чек-лист дня** — то, что нужно проверить до конца дня; счётчик «выполнено / всего».
6. **Напоминания** — время и текст; наступившие помечаются «пора». Подсветка при открытии стола,
   системных push-уведомлений нет.
7. **Заметки** — свободный текст с автосохранением (пауза 0,7 с после ввода).
8. **Документы и ИИ-проверка** — см. раздел 4.
9. **Работа с телефона** — см. раздел 5.

## 4. Документы и ИИ-проверка

Загрузка перетаскиванием или выбором файла: **TXT, MD, CSV, JSON, PDF, изображения**, до 20 МБ.

Проверка возвращает:
- вердикт — «замечаний нет» / «требует внимания» / «есть риски»;
- краткий вывод и ключевые положения;
- риски с уровнями (высокий / средний / низкий);
- чего в документе не хватает;
- **предлагаемые задачи** с готовой оценкой сложности, часов и приоритета — добавляются в план одной кнопкой.

Ограничения по форматам:
- текстовые файлы (TXT, MD, CSV, JSON) читаются автоматически;
- изображения разбираются, если среда просмотра поддерживает работу с картинками;
- **из PDF текст автоматически не извлекается** — для него в карточке документа есть поле
  «вставьте фрагмент», после сохранения текста проверка работает обычным порядком;
- форматы Word (.docx) хранилищем не принимаются — сохраняйте в PDF или TXT.

ИИ-проверка расходует лимиты того, кто её запускает, и спрашивает разрешение при первом вызове.

## 5. Привязка к телефону

Стол хранит данные не в браузере, а на своей стороне, поэтому телефон и компьютер видят один план:
отметили задачу на телефоне — на компьютере она обновилась сама.

Порядок подключения:
1. Навести камеру телефона на QR-код в блоке «Работа с телефона» (он уже нарисован).
2. Войти под той же рабочей учётной записью.
3. В браузере телефона: «Поделиться» → «На экран «Домой»» — стол открывается как приложение.

Ссылка продублирована текстом с кнопкой копирования. Внизу блока — индикатор состояния:
**синхронизировано** (зелёный) или **автономный режим** (жёлтый — правки сохраняются только
в текущем браузере, до восстановления связи).

На узком экране макет перестраивается в одну колонку, сверху появляется липкая лента переходов
по разделам.

## 6. Как устроены данные

Хранилище документов рабочего стола, коллекции и поля:

| Коллекция | Поля |
|---|---|
| `tasks` | `title`, `tier` (light/medium/heavy), `hours`, `priority` (crit/high/norm), `status` (plan/done), `date` (ГГГГ-ММ-ДД), `goal` (id цели), `createdAt`, `doneAt`, `source` (имя документа, если задача пришла из ИИ-проверки) |
| `goals` | `title`, `due`, `createdAt` |
| `checklist` | `text`, `done`, `date` |
| `reminders` | `text`, `time`, `date`, `done` |
| `docs` | `name`, `assetId`, `type`, `size`, `at`, `review`, `reviewAt`, `pasted` |
| `notes/main` | `text`, `updatedAt` |
| `settings/main` | `capacity` (норма часов), `shareUrl` (ссылка для QR-кода) |

Дополнительно всё состояние зеркалится в память браузера — стол открывается мгновенно,
ещё до подключения к хранилищу, и продолжает работать при обрыве связи.

Возможности среды, объявленные страницей: `db` (общие данные), `assets` (файлы документов),
`sample` (ИИ-проверка).

## 8. Обновление

Страница собрана из одного файла `planerka15.html`. Чтобы изменить стол — правится файл
и публикуется по той же ссылке; адрес и все накопленные данные при этом сохраняются.

## 9. Публичная версия на GitHub Pages

Статический сайт собирается из `planerka15.html` скриптом `build/build.ps1`: он добавляет
обёртку HTML-документа, подставляет адрес сайта в QR-код, кладёт демонстрационный рабочий день
(даты считаются от сегодняшнего) и включает честные подписи об автономном режиме.

Что в публичной версии **работает**: календарь нагрузки, план по структуре сложности, цели,
завершённые, чек-лист, напоминания, заметки, таймер планёрки, шкала объёма, мобильный макет.

Что **не работает** и почему: на статическом хостинге нет ни общего хранилища, ни доступа к модели,
поэтому отключены загрузка документов и ИИ-проверка, а план хранится в браузере устройства —
телефон и компьютер ведут отдельные списки. Всё это доступно в рабочей версии на claude.ai.

Пересборка и публикация изменений:

```
powershell -File build/build.ps1
git -C repo add -A && git -C repo commit -m "..." && git -C repo push
```

## 10. Известные ограничения

- Напоминания подсвечиваются при открытии стола; системных уведомлений телефона нет.
- Из PDF текст для ИИ-проверки вставляется вручную.
- Файлы .docx хранилищем не принимаются.
- Живая страница визуально не проверялась при сборке — встроенный браузер не был авторизован.
